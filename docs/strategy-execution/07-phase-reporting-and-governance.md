# Phase 7: Reporting and Governance

## Purpose

This phase turns reports into the formal evidence, accountability, and governance layer for strategy execution.

Reports should not only summarize tasks, KRAs, KPIs, and objectives. They should prove the execution chain from Strategic Goal to evidence, expose missing links, identify overdue strategic work, and support scheduled accountability.

## Reporting Design Principle

Every strategic report should answer:

- What scope is being reported?
- Which strategy items are included?
- What progress calculation was used?
- What evidence supports the reported progress?
- Which records are missing links or governance data?
- Who owns the next action?

Reports must use the same graph service from Phase 3 and progress engine from Phase 4.

## Required Report Types

| Report | Purpose | Primary Audience |
| --- | --- | --- |
| Strategic Execution Traceability Report | Shows the chain from Strategic Goal to Task evidence. | Executives, strategy owners, auditors. |
| Division/Unit Progress Heatmap | Shows progress, status, and linkage health by division and unit. | Executives, division heads, managers. |
| KRA/KPI Evidence Report | Shows KPI results, linked tasks, completion dates, and evidence. | Managers, KPI owners, reviewers. |
| Unlinked Records Report | Shows tasks, KPIs, KRAs, objectives, divisions, and units with missing links. | Admins, governance reviewers, data stewards. |
| Overdue Strategic Tasks Report | Shows strategic tasks that are late, blocked, or missing evidence. | Managers, division heads. |
| Owner Accountability Report | Shows owners, assignees, progress, overdue work, and missing evidence. | Leadership, HR/governance, managers. |
| Progress Variance Report | Shows mismatches between cached progress and graph-calculated progress. | Admins, technical owners, auditors. |
| KPI Review Governance Report | Shows KPI review status, review authority, rejected/submitted items, and pending approvals. | KPI reviewers, governance owners. |

## Required Report Metadata

Every generated report should display:

- Report title.
- Report type.
- Scope: personal, unit, division, corporate, or audit.
- Date range.
- Data source summary.
- Generated by.
- Generated at.
- Progress formula or calculation source.
- Included categories.
- Linkage health summary.
- Diagnostic count.
- Export timestamp, when exported.

This metadata must appear in the preview and exported output.

## Report Structure

Every strategic report should include these sections where applicable:

1. Executive summary.
2. Scope and metadata.
3. Progress summary.
4. Strategy traceability rows.
5. Division/Unit contribution rows.
6. KRA/KPI evidence rows.
7. Overdue or blocked task rows.
8. Linkage diagnostics.
9. Owner accountability.
10. Recommended next actions.

## Evidence Rules

Evidence can include:

- Completed task status.
- Completion date.
- Checklist item completion.
- Task comment.
- Attachment.
- KPI review note.
- KPI approval/rejection.
- Audit event.
- Report generation timestamp.

Completed strategic work should ideally have at least one evidence signal. If a task or KPI is marked complete without evidence, reports should flag it as a governance warning.

## Governance Rules

Governance should cover:

- KPI review status.
- KPI review authority.
- KPI owner.
- Evidence requirements for completed strategic tasks.
- Audit trail for progress changes.
- Audit trail for linkage changes.
- Report generation history.
- Report delivery history.
- Diagnostic resolution history.

Governance should distinguish:

- Work not started.
- Work in progress.
- Work completed with evidence.
- Work completed without evidence.
- Work blocked.
- Work overdue.
- Work unlinked.
- Work outside the selected scope.

## Scheduled Reports

Scheduled reports must support:

- Unit scope.
- Division scope.
- Corporate scope.
- Audit/admin scope.
- One-time custom date range.
- Rolling custom date range.
- Daily, weekly, monthly, quarterly, half-yearly, and yearly periods where supported.

Each schedule should track:

- Schedule owner.
- Recipient email.
- Optional manager/CC email.
- Scope.
- Division.
- Unit.
- Frequency.
- Categories.
- Preferred send time.
- Preferred day/day-of-month.
- Last sent time.
- Next send time.
- Delivery status.
- Delivery error, if any.
- Whether the schedule is active.

## Schedule Lifecycle

The schedule lifecycle should be explicit:

```text
Draft / Saved
-> Active
-> Due
-> Generating
-> Sent
-> Updated Next Send
```

Failure path:

```text
Due
-> Generating
-> Failed
-> Error Captured
-> Retry / Manual Review
```

One-time schedule path:

```text
Active
-> Due
-> Sent
-> Deactivated
```

The frontend and backend should distinguish schedule metadata from actual report delivery. Power Automate or a worker may perform delivery, but the report contract must define the fields it reads and updates.

## Export Requirements

CSV and future document exports should include hierarchy rows, not only summary totals.

Minimum export columns:

- Scope.
- Strategic Goal.
- Organisational KRA / Key Deliverable.
- Division.
- Unit.
- Objective / Initiative.
- Performance KRA.
- KPI.
- Task.
- Owner/assignee.
- Progress.
- Status band.
- Calculation source.
- Due date.
- Completion date.
- Evidence count.
- Diagnostic count.
- Next action.

## Admin And Audit View

Audit/admin reporting should expose:

- All schedules by owner and scope.
- Failed schedules.
- Due schedules.
- Reports generated but not delivered.
- Reports delivered without updated `LastSentAt`.
- Schedules missing `NextSendAt`.
- Linkage diagnostics by severity.
- Progress variance between cached and graph-calculated values.

## Implementation Order

Recommended reporting order:

1. Update report metadata and scope display.
2. Add graph-backed traceability report rows.
3. Add Division/Unit heatmap data from the graph/progress engine.
4. Add unlinked records and diagnostics report.
5. Add evidence report and overdue strategic tasks report.
6. Expand CSV export to hierarchy rows.
7. Strengthen report schedule scope and delivery lifecycle fields.
8. Add admin/audit schedule and delivery views.
9. Add KPI review governance report.

## Report Acceptance Criteria

- A report can show how a Strategic Goal is supported by Organisational KRAs, Performance KRAs, KPIs, tasks, and evidence.
- A Division/Unit heatmap uses the same progress values as the Strategy page for the same scope.
- CSV/export includes hierarchy rows, not only summary totals.
- Unlinked records are visible and actionable.
- Scheduled reports clearly state scope, next send time, last sent time, and delivery state.
- Reports distinguish completed work with evidence from completed work without evidence.
- Audit/admin views can identify failed schedules, missing links, and progress variance.
