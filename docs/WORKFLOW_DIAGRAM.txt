================================================================================
                              KEY FIXES APPLIED
================================================================================

1. CUSTOM NAVIGATION CLIENT (CustomNavigationClient.ts)
   ────────────────────────────────────────────────
   Problem: Full page reloads during MSAL redirect lost React context
   Fix:     Intercepts MSAL navigation, routes through React Router
   Result:  Tokens stay intact, MSAL context preserved, smooth UX

2. EMPLOYEE EMAIL PERSISTENCE (hrSharePointService.ts:633)
   ────────────────────────────────────────────────────
   Problem: EmployeeEmail never stored in SharePoint
   Fix:     Added to itemData.fields on submission
   Result:  Later approval steps can notify employee

3. NOTIFICATION SPLIT (hrSharePointService.ts:868)
   ──────────────────────────────────────────────
   Problem: All emails gated behind employeeEmail check
   Fix:     Split into two independent checks:
            - Employee email: IF emailCtx?.employeeEmail
            - Next approver: IF nextStage !== 'Approved' AND emailCtx
   Result:  Chain continues even if employee email is missing

4. EMAIL CONTEXT CONSTRUCTION (useLeaveApprovals.ts)
   ────────────────────────────────────────────────
   Problem: emailCtx undefined if employeeEmail missing
   Fix:     Construct emailCtx based on division/unit availability
   Result:  Approver lookup always has division/unit info

5. EMAIL BUTTON URLs (hrEmailService.ts)
   ───────────────────────────────────────
   Problem: Single "Review & Action" button → full dashboard
   Fix:     Two buttons → lightweight /leave-action page
   Result:  One-click approval experience

================================================================================
                           AUTHENTICATION FLOW
================================================================================

Email Button Click
       │
       ├─→ /leave-action?requestId=42&action=approve
       │
       ├─→ ProtectedRoute checks: isAuthenticated?
       │       │
       │       ├─ YES → LeaveActionPage renders
       │       │
       │       └─ NO → Redirect to /login
       │           │
       │           └─→ User clicks "Sign in with Microsoft"
       │               │
       │               └─→ instance.loginRedirect()
       │                   │
       │                   ├─ MSAL records: "I was called from /login"
       │                   ├─ Browser redirects to Microsoft login
       │                   └─ User signs in
       │
       ├─ Microsoft redirects back to /
       │   │
       │   └─→ MsalAuthProvider initializes:
       │       ├─ Calls handleRedirectPromise()
       │       ├─ Processes auth code → stores tokens
       │       ├─ CustomNavigationClient INTERCEPTS next navigation
       │       └─ navigateToLoginRequestUrl: true → MSAL wants to go back to /login
       │
       ├─→ CustomNavigationClient.navigateInternal('/login')
       │   │
       │   └─→ Calls React Router's navigate('/login')
       │       │
       │       └─ [NO full page reload — React tree stays alive!]
       │
       ├─→ Login.tsx renders
       │   │
       │   └─→ useEffect sees isAuthenticated=true
       │       │
       │       └─→ reads sessionStorage['auth_return_to'] = "/leave-action?..."
       │           │
       │           └─→ navigate('/leave-action?requestId=42&action=approve')
       │
       └─→ LeaveActionPage renders with request details
           │
           └─→ User can now confirm the approval!

KEY INSIGHT: CustomNavigationClient + navigateToLoginRequestUrl + sessionStorage
             backup = deep-link preservation that survives Microsoft OAuth flow


================================================================================
                              ERROR HANDLING
================================================================================

Scenario                                 Handling
─────────────────────────────────────────────────────────────────────────────
Request already approved/rejected        LeaveActionPage: "Request not found"
                                         Suggests: "View Leave Approvals"

Missing division/unit for approver       Approver lookup fails (try-catch)
lookup                                   Chain continues, approver doesn't get notified
                                         (configure workflow approvers in admin)

Missing employee email (old requests)    Employee doesn't get status update
                                         Next approver STILL gets notified (chain ok)

Network error during approval            LeaveActionPage: "Approval failed"
                                         Approver can retry or use dashboard

Invalid requestId in URL                 LeaveActionPage: "Request not found"
                                         (typo in email link)

Session expires mid-approval             useApproveLeave catch: "Please log in again"
                                         (rare; MSAL refreshes tokens automatically)
